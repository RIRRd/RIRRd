Self-hosted software

What you can run today.

RIRRd runs independently. The public community network is a separate service at irrd.tools.

An embedded database

An embedded database, bounded query services and a bundled console. PostgreSQL and Redis are not required to run RIRRd.

Installation & configuration →

Optional RPKI validation

Validate ROAs with the embedded Routinator-based engine, check route origins over HTTPS and connect a router to a local RTR listener. Enable it when you need it.

RPKI coverage & limitations →

BIRD and FRR integration

Generate IRR filters with bgpq4 and use a local RTR cache for origin validation. The guides keep these two jobs separate and include verification steps.

How to interpret these results

The numbers are historical development measurements at the exact revisions in the raw results, not a capacity promise for the current beta. Both systems used the same synthetic fixture and recorded host conditions. Memory includes the reference application and its PostgreSQL/Redis services; filesystem cache outside processes is excluded.

The benchmark exercises a shared subset of query features. It does not establish feature parity. Real-world datasets, sustained load and integrated RPKI need separate sizing. Full authentication, policy, replication and release qualification remain in development.

Report reproducible bugs, query differences or performance regressions through GitHub Issues. Avoid posting credentials or private registry data.
