RIRRd and IRRd

This checkpoint compares RIRRd with official IRRd v4.5.4, our pinned compatibility baseline. A matching test establishes the behavior exercised by that test.

Evidence at this checkpoint

  • 39 TCP and 39 HTTP WHOIS cases matched pinned IRRd.
  • 10 organisation schema cases passed against the upstream parser.
  • Supported organisation GraphQL values and nine field types matched upstream.
  • 131 unit tests and 11 integration tests passed locally on Linux.
  • A 61-second RPSL fuzz run completed 1,066,347 executions without a crash.

These are local results. New private-repository CI results have not been independently verified from this session.

Method, versions and limits

Debian 13 x86-64; previous VM configuration: 8 CPUs and 31 GiB RAM. Eight client threads, 20 warmups, a new TCP connection per request, reference followed by candidate, one measured run. No build or fuzz workload ran during timing. Both implementations used the six-object synthetic fixture and their recorded development configuration. The upstream oracle used one WHOIS worker.

RIRRd code: acb6cac. IRRd: 8e8080dab744a348b7d0e6efcb53f403301dd075 (v4.5.4). The RIRRd release binary and pinned upstream Docker image ran on the same host.

The VM has since been upgraded to 24 CPUs and 62 GiB RAM. The figures above predate that upgrade. They do not measure full feature parity, realistic registry scale, sustained capacity or equivalent peak memory. Broader performance claims require repeated, controlled workloads and larger licence-cleared datasets.

WORK AHEAD

Closing the compatibility gaps

  1. Authorisation and object workflows

    Remaining classes and reference rules, key certificates/OpenPGP, scoped tokens, overrides, suspension, accounts, mail and notifications.

  2. Mirroring and recovery

    Signed NRTMv4 publication and scheduling, retention and recovery, and replication tests in both directions with official IRRd.

  3. Queries and live policy

    Broader WHOIS and GraphQL parity, source aliases, live RPKI refresh, scope filtering and route preference.

  4. Release qualification

    Linux x86-64/ARM64 packaging, upgrades and rollback, security review, migration, signing and sustained load.
