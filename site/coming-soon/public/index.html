  • 39 TCP and 39 HTTP WHOIS cases matched pinned IRRd.
  • 10 organisation schema cases passed against the upstream parser.
  • Supported organisation GraphQL values and nine field types matched upstream.
  • 47 authoritative HTTP decision cases and 25 policy-set/router schema cases matched pinned IRRd.
  • 134 unit tests and 13 integration tests passed locally on Linux.
  • Two 121-second RPSL fuzz runs completed 3,210,445 executions in total without a crash.

These are local results. New private-repository CI results have not been independently verified from this session.

EARLY MEASUREMENT · UPGRADED VM

The current synthetic comparison

This smoke test uses six objects and one exact-key WHOIS query on a 24-CPU, 62-GiB Debian VM. IRRd uses eight WHOIS worker processes; RIRRd is capped at eight connections. Eight client threads query one implementation at a time.

Five runs alternate which implementation goes first. Each run includes 20 warmups and 1,000 measured requests per implementation, using a new TCP connection for each request. No build or fuzz workload ran during timing.

The previous one-run smoke on the 8-CPU, 31-GiB VM configured IRRd with one WHOIS worker. Its worker count and host configuration differ from the current comparison; those figures are historical context.

Memory snapshots and database sizes use different accounting scopes and are not presented as equivalent peak-memory results. Broader performance claims require repeated controlled workloads, licence-cleared larger datasets, sustained testing and fuller compatibility.

WORK AHEAD

Closing the compatibility gaps

  1. Authorisation and object workflows

    Remaining classes and reference rules, key certificates/OpenPGP, scoped tokens, overrides, suspension, accounts, mail and notifications.

  2. Mirroring and recovery

    Signed NRTMv4 publication and scheduling, retention and recovery, and replication tests in both directions with official IRRd.

  3. Queries and live policy

    Broader WHOIS and GraphQL parity, source aliases, live RPKI refresh, scope filtering and route preference.

  4. Release qualification

    Linux x86-64/ARM64 packaging, upgrades and rollback, security review, migration, signing and sustained load.
