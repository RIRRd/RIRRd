# RIRRd 0.1.0-beta.2

This beta focuses on lightweight self-hosted Internet Routing Registry hosting.
It is not production qualified and full IRRd query, authorization and replication
parity remain incomplete. Source, bugs and contributions now live in the dedicated
[RIRRd organization](https://github.com/RIRRd/RIRRd).

## Changes

- Remove the experimental embedded RPKI validator, ROA-file policy, origin-check
  APIs and RTR service, including the Routinator dependency. Use a separate
  validator when your router policy needs cryptographic origin validation.
- Keep the IRR database, WHOIS/HTTP/GraphQL queries, NRTMv3 mirroring, source
  health, console and BIRD/FRR IRR filter examples.
- Retire RPKI dashboard controls and monitoring requests. Existing aggregate IRR
  history survives the telemetry format change.
- Publish contribution, issue and security entry points under RIRRd/RIRRd with
  MIT licensing and explicit AI-assisted development disclosure.

## Upgrade

Stop the service and back up the database, configuration and installed binary.
Remove `[rpki]`, `authoritative_roa_file` and
`authoritative_roa_exempt_sources`; these settings now fail configuration checks.
Run `rust-irrd --config /etc/rust-irrd/irrd.toml config check` before restarting.
There is no database schema change in this release; existing IRR objects and
source serials remain compatible. Retired `/v1/rpki/*` endpoints return 404.

See [beta status](https://rirrd.co.uk/docs/beta/) for known gaps and
[testing](https://rirrd.co.uk/testing/) for verification at the recorded commits.
Historical performance numbers are not current release capacity guarantees.
