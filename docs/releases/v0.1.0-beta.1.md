# RIRRd 0.1.0-beta.1

First beta candidate of the Rust Internet Routing Registry daemon. Full IRRd
parity and production qualification are incomplete; use this release for isolated
evaluation and read-only tests. Linux is the primary platform.

The daemon combines embedded IRR storage, bounded WHOIS/HTTP/GraphQL queries,
source-aware AS-set expansion, atomic NRTMv3 mirroring, verified backup/restore,
bounded authoritative workflows and a self-hosted console. An optional validator
integrates the attributed NLnet Labs Routinator/rpki-rs libraries in the same
process, with private local RTR and HTTPS origin checks.

This beta adds covering-ROA explanations, 100-route atomic batch validation,
trust-anchor/address-family statistics and an index construction path that avoids
formatting/reparsing every verified prefix. Graphs show real node activity,
source counts, resources and validator contributions; history is never generated
to fill missing observations.

Project documentation and recorded benchmark comparisons are at **rirrd.co.uk**.
The independent community network, public node directory, live queries and private
reviewed node submissions are at **irrd.tools**. The first node is in the United
Kingdom, hosted by HYEHOST LLC. Self-hosting does not require a community account.

Known gaps include authentication/accounts/OpenPGP/mail, remaining class/reference
behavior, NRTMv4 publication/scheduling/recovery, bidirectional replication,
live RPKI/scope/route-preference suppression, broader query parity and sustained
release qualification. RRDP-only validation excludes rsync-only repositories;
rejected publication points are disclosed. No public registry write/admin API is
provided by the community node.

Code is MIT licensed. Dependencies and registry data retain their own terms.
The project is built with AI assistance; human and AI-assisted contributions are
welcome with review and tests. Report reproducible beta bugs through GitHub
Issues; follow SECURITY.md for private security reports.

Native Debian/RPM artifacts target Linux x86-64 and ARM64. Verify SHA256SUMS and
the platform metadata before installation. These checksums provide integrity,
not an independent release signature. Installations require explicit configuration
and service startup. CI artifacts are published only after the release workflow's
checks pass; a source tag alone does not assert that binary artifacts exist.
