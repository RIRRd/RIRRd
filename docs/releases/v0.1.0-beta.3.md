# RIRRd 0.1.0-beta.3

This beta brings the development work since beta.2 into a single release:
broader IRR data coverage, bounded query memory, safer authoritative updates,
database repacking and a redesigned self-hosted console. RIRRd remains an
evaluation release. Full IRRd parity and production qualification are incomplete.

## Registry and query changes

- Retain and browse all 19 standard IRRd object classes when using a full-data
  mirror profile. Routing-only profiles remain available for smaller hosts.
  Source configuration, upstream availability and local policy still determine
  what an individual instance contains.
- Support explicit upstream wire encodings, larger bounded snapshot records,
  filtered NRTMv3 catch-up and older upstream idle replies. Queue mirror work per
  upstream so multiple sources sharing a peer do not consume all query workers.
- Apply bounded native HTTP admission, with configurable limits and explicit
  overload responses. Limits protect the service; they are not a capacity claim.
- Add indexed GraphQL reference filters and broader `!j` source status queries.
  Reject requests that exceed result, scan or materialization limits instead of
  silently returning an incomplete answer. The full upstream schema remains open.
- Prevent takeover of referenced contact names, support atomic deletion of an
  object and all its referrers, and coordinate query snapshots with mirror and
  submission writes without blocking the asynchronous runtime on the store lock.
- Withhold private certificate material and converted owner identifiers from
  public responses, alongside existing credential redaction.

## Storage and resource use

- Add verified database repacking, including a bounded online copy from a stable
  snapshot. Repacking writes a separate file, verifies its content and preserves
  source serials and metadata. It does not replace the serving database for you.
- Reduce allocation during snapshot import, verification, export and rejected
  large queries. Portable optimized release builds use ThinLTO and strip debug
  information; no host-specific CPU instruction set is required.
- Distinguish process memory, service file cache and configured limits. Resource
  history separates maintenance from normal serving and identifies stale data.

Recorded measurements are workload-specific: a full development database was
repacked from approximately **28 GiB to 20 GiB** without removing records. A
synthetic rejected-large-query test reduced median peak RSS from **45.35 MiB to
17.16 MiB**. The normal one-CPU query benchmark showed similar memory and slightly
lower throughput, so this release does **not** claim a general throughput gain.
See the [storage checkpoint](https://github.com/RIRRd/RIRRd/blob/v0.1.0-beta.3/docs/benchmarks/STORAGE_FULL_2026_11_05.md) and
[development review](https://github.com/RIRRd/RIRRd/blob/v0.1.0-beta.3/docs/compatibility/DEVELOPMENT_REVIEW_2026_11_05.md) for exact
commits, datasets, repetitions, limits and commands.

## Console and documentation

The bundled console has a clearer overview, grouped navigation, responsive
layouts and better query guidance. IPv4, IPv6, AS-set membership, source browsing,
HTTP/GraphQL commands and BIRD/FRR examples remain available without third-party
assets or a community account. The project and community websites are maintained
separately; their platform source is not part of the MIT daemon distribution.

## Upgrade and rollback

1. Stop the instance and back up its database, configuration and installed binary.
   Keep sufficient free disk space for both the original and any repacked file.
2. Install the matching Linux x86-64 or ARM64 DEB/RPM after verifying the release
   `SHA256SUMS`. Run `rust-irrd --config /etc/rust-irrd/irrd.toml config check`
   before restarting, then verify source status and representative queries.
3. A beta.2 database does not require an automatic schema conversion. Repacking
   is optional; follow the [storage guide](https://github.com/RIRRd/RIRRd/blob/v0.1.0-beta.3/docs/operations/STORAGE_MAINTENANCE.md). Do not copy
   an actively written database file or overwrite the serving generation.
4. For rollback, stop the service and restore the saved binary and configuration.
   Restore the matching database backup if the previous version cannot represent
   newly imported classes or changed source policy; validate it before serving.

Configuration added after beta.2 must be removed when rolling back to that older
binary. Operators upgrading from beta.1 must also remove the retired RPKI
settings described in the [beta status](https://github.com/RIRRd/RIRRd/blob/v0.1.0-beta.3/docs/BETA_STATUS.md). RPKI validation and
RTR remain deliberately separate from RIRRd.

```sh
bash install.sh --version 0.1.0-beta.3 --download-only /tmp/rirrd-package
sudo bash install.sh --version 0.1.0-beta.3
```

## Qualification and remaining work

Release publication is gated on the Linux x86-64/ARM64 and Windows core checks,
browser workflows, dependency audit, source coverage, official IRRd 4.5.4 oracle,
router integration, Docker smoke tests, fuzzing, history secret scan and native
DEB/RPM installation/systemd checks. Passing checks cover their fixtures, not full
parity or arbitrary sustained production load.

Account and OpenPGP workflows, mail processing and notifications, remaining
authorization/reference semantics, complete NRTMv4 publication and recovery,
broader query compatibility and live policy suppression remain unfinished.
See [known gaps](https://github.com/RIRRd/RIRRd/blob/v0.1.0-beta.3/docs/BETA_STATUS.md). Use this beta at your own risk, test generated
routing policies independently, and report reproducible issues at
[RIRRd/RIRRd](https://github.com/RIRRd/RIRRd/issues). AI-assisted development and
community contributions remain subject to review and reproducible tests.
