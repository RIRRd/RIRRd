# RIRRd 0.1.0-beta.5

This patch fixes filtered RIPE mirroring stopping at publisher-specific poetry
records and improves large source-count formatting in the bundled console.
It includes all beta.4 changes and remains beta software: full IRRd parity and
production qualification are incomplete.

## Mirroring correction

RIPE NRTMv3 can include `poem` and `poetic-form` records alongside standard IRR
objects. Earlier releases rejected these before applying the configured class
filter, stopping the feed. A filtered reader now validates their structure,
identity, source and framing; the configured standard-class filter excludes
them while later supported updates and the final serial commit atomically.

Strict snapshot and authoritative parsers still reject these extensions.
Unknown classes, malformed records, wrong sources and broken framing still
fail instead of silently advancing the cursor. New regressions exercise both
extension classes, retained routing data, serial advancement and failure cases
through the normal Rust build suite.

The fix was used during recovery of both hosted nodes on 17 November. Their
replacement dataset passed native integrity verification for 14,006,896 objects
before activation. Hosted snapshot download retries, staging cleanup and mirror
endpoint repairs are separately maintained operator changes; they are not a
snapshot scheduler shipped in this package. The new
[source freshness and recovery guide](https://github.com/RIRRd/RIRRd/blob/v0.1.0-beta.5/docs/operations/SOURCE_RECOVERY.md)
explains the boundary, monitoring and self-hosted safeguards. No patch can
guarantee upstream availability or eliminate the need to monitor freshness.

## Console

Large object counts remain readable at narrow dashboard widths. This is a
formatting improvement; source dates, freshness thresholds and data totals are
not altered to conceal delayed updates.

## Upgrade

Stop the daemon and back up its database, configuration and installed binary.
Download the matching x86-64 or ARM64 DEB/RPM, installer and `SHA256SUMS` from
this release. Verify the downloaded installer before running it as described
in the [installation guide](https://github.com/RIRRd/RIRRd/blob/v0.1.0-beta.5/docs/operations/GETTING_STARTED.md):

```sh
sha256sum --ignore-missing --check SHA256SUMS
bash install.sh --version 0.1.0-beta.5 --download-only /tmp/rirrd-package
# Or install the verified package:
sudo bash install.sh --version 0.1.0-beta.5
```

Run `config check`, restart and inspect source status and representative complete
query answers. A feed whose old serial has expired needs a matching fresh
snapshot; do not set its cursor to the latest advertised serial without the
corresponding data. No storage-format migration or reimport is required solely
because of this patch. Stop and restore the saved binary/configuration to roll
back; retain a matching database backup.

## Qualification and limits

Publication is gated on Linux x86-64/ARM64 and Windows core tests, strict Clippy,
formatting, dependency audit, browser and coverage contracts, pinned official
IRRd 4.5.4 oracle, BIRD/FRR integration, Docker smoke checks, fuzzing, source and
history hygiene, and native DEB/RPM install/systemd tests. See the
[tag's workflow](https://github.com/RIRRd/RIRRd/actions/workflows/beta-release.yml)
for the final results. Existing performance measurements belong to their exact
tested commits; this patch makes no new throughput or storage-reduction claim.

Accounts/tokens, OpenPGP/key-cert, mail workflows, remaining authorization and
query semantics, NRTMv4 scheduling/publication/recovery and live scope/route
preference suppression remain open. RPKI validation and RTR are deliberately
separate. Read [beta status](https://github.com/RIRRd/RIRRd/blob/v0.1.0-beta.5/docs/BETA_STATUS.md),
test independently and report reproducible issues through
[GitHub Issues](https://github.com/RIRRd/RIRRd/issues).
The daemon and bundled console remain MIT licensed. Development uses AI
assistance; human and AI-assisted contributions require review and tests.
