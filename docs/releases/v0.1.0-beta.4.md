# RIRRd 0.1.0-beta.4

This beta improves large-query reliability, keeps queries responsive during
mirror commits, broadens authoritative updates and source selection, and gives
the self-hosted console a consistent visual theme. Full IRRd parity and
production qualification remain incomplete.

## Query reliability and resource bounds

- Pin one committed database snapshot for each WHOIS request and complete
  GraphQL operation. Mirror commits can proceed without blocking queries behind
  a global read lock; aliases within a GraphQL request see the same version.
- Return complete large transit-set prefix lists within explicit finite budgets.
  Bound traversal, computation, response bytes, concurrent heavy work and slow
  downloads. Capacity, resource-limit and timeout failures return explicit errors
  rather than a successful partial routing list.
- Avoid allocating an asynchronous resolver per prefix in large GraphQL arrays.
  Preserve schema validation, selections, aliases and directives.
- Preview large results without rendering millions of browser elements. Full
  responses remain available for copying or downloading; replacing a result
  releases its retained browser resources.

The recorded full-catalog correctness run returned **3,514,991 prefixes** in one
complete result with peak daemon RSS of **648.5 MiB**. The earlier dev mirror-write
qualification completed **16,078/16,078 HTTP 200 replies** at about 230 starts/s,
including a real RADB commit, with no rejected or failed requests. These are
specific warm-cache tests on the shared VM, not Internet measurements or a claim
of unlimited capacity. Exact tested commits, response hashes, memory scope and
limitations are in [query qualification](https://github.com/RIRRd/RIRRd/blob/v0.1.0-beta.4/docs/compatibility/QUERY_SOURCE_PARITY.md).

## Authoritative and query compatibility

This release adds authenticated `inetnum`, `inet6num` and `irt` workflows, using
same-source maintainer and strong-reference checks. All 19 standard classes can
be mirrored; authoritative `key-cert`/OpenPGP workflows remain incomplete.
Named source groups preserve ordered source precedence across query interfaces.
Five more indexed GraphQL filters (`members`, `mpMembers`, `person`, `role` and
`origin`) bring the supported inverse filters to eleven. Bounded selectivity
probes make sparse intersections work even when another predicate has thousands
of candidates; all scans retain cancellation and work limits.
These additions are compared with the pinned official IRRd 4.5.4 baseline;
they do not establish complete authorization or query parity.

## Console

A shared routing mark, navy-and-teal palette, accessible controls and consistent
status colours replace mismatched branding. The bundled console stays independent
and MIT licensed. Project/community website code remains separately maintained.

## Upgrade and rollback

1. Stop the daemon and back up its database, configuration and installed binary.
2. Verify the release `SHA256SUMS`, install the matching Linux x86-64/ARM64 package,
   run `rust-irrd --config /etc/rust-irrd/irrd.toml config check`, and restart.
3. Verify source status and representative complete query responses before using
   generated router policy. Public fairness limits are separate from query capacity.
4. Roll back by stopping the daemon and restoring the saved binary/configuration.
   Remove new configuration settings before using an older binary. Keep a matching
   database backup for rollback after authoritative updates.

There is no automatic storage-format migration in this beta. The existing
[storage maintenance guide](https://github.com/RIRRd/RIRRd/blob/v0.1.0-beta.4/docs/operations/STORAGE_MAINTENANCE.md)
continues to apply. RPKI validation and RTR remain separate from RIRRd.

Download and verify `install.sh` and `SHA256SUMS` from the release assets as
described in the [installation guide](https://github.com/RIRRd/RIRRd/blob/v0.1.0-beta.4/docs/operations/GETTING_STARTED.md), then run:

```sh
bash install.sh --version 0.1.0-beta.4 --download-only /tmp/rirrd-package
sudo bash install.sh --version 0.1.0-beta.4
```

## Qualification and remaining work

Publication requires the core Linux x86-64/ARM64 and Windows checks, browser tests,
dependency audit, source coverage, official oracle, BIRD/FRR integration, Docker
smoke tests, fuzzing, history secret scan and native DEB/RPM installation/systemd
checks. The new regression cases run through the normal build workflows.

Accounts, scoped API tokens, OpenPGP/key-cert, mail submission and notifications,
NRTMv4 scheduling/publication and full recovery interoperability, live scope and
route-preference suppression, broader query compatibility and sustained production
qualification remain open. See [beta status](https://github.com/RIRRd/RIRRd/blob/v0.1.0-beta.4/docs/BETA_STATUS.md).
Use this beta at your own risk, test routing policy independently, and report
reproducible problems through [GitHub Issues](https://github.com/RIRRd/RIRRd/issues).
AI-assisted development and contributions remain subject to review and tests.
