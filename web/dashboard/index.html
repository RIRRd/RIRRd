Choose sources deliberately

Use the databases appropriate to your peers and allocations. A fast query cannot correct stale or incorrectly authorised source data.

Freshness is an operational property

A mirror starts from a snapshot with its matching serial, then polls for changes. A successful check means the peer answered; it does not guarantee zero propagation delay. Sources without a verified incremental feed remain daily snapshots. Live RPKI/scope/preference filtering is still incomplete.

Service boundaries

Public access permits read-only queries. Authoritative updates, account administration, journal exports and mirroring endpoints are private. The HTTP gateway limits queries to 2 per second per IP with a burst of 20, and responses to 2 MiB. The console displays at most 1 MiB.

BIRD & FRROUTING

Keep the tools you know.

Point your filter generator at your RIRRd instance, then validate the generated router policy.

01

Run RIRRd privately

Choose trusted sources and load a licensed snapshot or configure a verified mirror. Loopback and an SSH tunnel are suitable for local evaluation.

02

Generate filters

Use bgpq4 to query your instance and expand an AS-set into IPv4/IPv6 prefix lists. Pin the source list explicitly.

03

Validate, review, apply

Check BIRD or FRR syntax, review changes and retain the last known good policy. Router changes are an operator action.

Start with a local query

Use your private RIRRd WHOIS endpoint.

Synthetic example
bgpq4 -p -4 -b -h 127.0.0.1:4343 -S EXAMPLE -l DOCS_IN4 AS64496:AS-DOCS

The -p option is needed for the documentation ASNs in this fixture. Omit it for normal public-AS policy unless you deliberately accept reserved/private ASNs. This command generates text; it does not change a router.

BIRD

Generate a prefix-set definition and reference it in an inbound filter. Validate the complete candidate configuration before reconfiguration.

FRRouting

Generate named IPv4/IPv6 prefix lists and attach them to an inbound route-map. Use versioned names to avoid retaining stale entries.

IRR and RPKI work together

BIRD and FRR use the generated routing policy; they do not gain IRR validation merely by changing a daemon setting. Keep your independent RPKI validator and origin-validation policy in place.
